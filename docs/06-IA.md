## Pipeline RAG (Retrieval-Augmented Generation)

### Fluxo

```
INPUT do usuário:
  {
    type: 'PETICAO_INICIAL_CIVEL',
    caseId: 'uuid-xxx',
    area: 'CIVEL',
    facts: 'Cliente foi cobrado por...',
    askedValueCents: 5000000
  }
         │
         ↓
┌─────────────────────────────────────────────────┐
│  STEP 1: Build context query                    │
│  - Extrai keywords                            │
│  - Adiciona metadados (área, comarca, fase)   │
└──────────────┬──────────────────────────────────┘
               │
               ↓
┌─────────────────────────────────────────────────┐
│  STEP 2: Hybrid Retrieval (PGVector + FullText) │
│                                                  │
│  A. Vector search (cosine)                       │
│     embeddings(query, model="voyage-law-2")    │
│     WHERE legal_areas @> [CIVEL]               │
│     AND (tenant_id = X OR is_public = true)    │
│     LIMIT 30                                    │
│                                                  │
│  B. Full-text search (tsvector)                 │
│     to_tsquery('portuguese', 'cobrança abusiva │
│       & consumidor')                            │
│     LIMIT 20                                    │
│                                                  │
│  C. Sum + dedup                                  │
└──────────────┬──────────────────────────────────┘
               │
               ↓
┌─────────────────────────────────────────────────┐
│  STEP 3: Rerank (Cohere Rerank v3)              │
│  Top 30 → Top 12                                │
│  Critérios: relevância + atualidade + autoridade│
└──────────────┬──────────────────────────────────┘
               │
               ↓
┌─────────────────────────────────────────────────┐
│  STEP 4: Build prompt                           │
│                                                  │
│  System: persona Juris-Flow + tom jurídico     │
│  + regras de fundamentação obrigatória          │
│                                                  │
│  Context: top-12 docs formatados                │
│  - Súmula X do STJ (texto)                     │
│  - Acórdão Y do TJSP (trecho)                  │
│  - Tema Z do STF (tese)                        │
│                                                  │
│  User: schema do tipo de peça preenchido        │
└──────────────┬──────────────────────────────────┘
               │
               ↓
┌─────────────────────────────────────────────────┐
│  STEP 5: Call Anthropic                         │
│  - model = routeModel(type)                     │
│  - max_tokens = 8000                            │
│  - temperature = 0.5 (factual)                  │
│  - stream = true                                │
│  - extended thinking (opus)                     │
└──────────────┬──────────────────────────────────┘
               │
               ↓
         chunks → SSE / save draft
```

## Geração de Peça — Implementação Real

### Pseudocódigo

```typescript
async function generatePiece(
  type: PieceType,
  caseId: string | null,
  inputs: PieceInputs,
  userId: string
): Promise<{ pieceId: string }> {
  // 1. Persiste draft inicial
  const piece = await db.documents.create({
    data: {
      tenantId: user.tenantId,
      pieceType: type,
      caseId,
      title: suggestedTitle(type, inputs),
      status: 'DRAFT',
      origin: 'IA',
      createdBy: userId,
    }
  });

  // 2. Dispatch Inngest
  await inngest.send({
    name: 'piece/generate.requested',
    data: { pieceId: piece.id, type, inputs, userId, caseId }
  });

  return { pieceId: piece.id };
}

// Inngest function
export const pieceGenerate = inngest.createFunction(
  { id: 'piece-generate', name: 'Gerar peça com IA' },
  { event: 'piece/generate.requested' },
  async ({ event, step }) => {
    const { pieceId, type, inputs, caseId, userId } = event.data;

    await step.run('update-status-generating', () =>
      db.documents.update({
        where: { id: pieceId },
        data: { status: 'GENERATING' }
      })
    );

    // Buscar contexto RAG
    const context = await step.run('rag-search', () =>
      rag.search({ type, caseId, area: inputs.area, query: buildQuery(inputs) })
    );

    // Buscar schema do tipo de peça
    const schema = pieceRegistry[type];

    // Construir prompt
    const prompt = buildPrompt({
      system: PIECE_SYSTEM_PROMPT,
      type,
      schema,
      inputs,
      context,
    });

    // Stream Anthropic
    let accumulated = '';
    const stream = await anthropic.messages.stream({
      model: routeModel(type),
      max_tokens: 8000,
      system: PIECE_SYSTEM_PROMPT,
      messages: [{ role: 'user', content: prompt }],
    });

    for await (const chunk of stream) {
      if (chunk.type === 'content_block_delta' && chunk.delta.type === 'text_delta') {
        const token = chunk.delta.text;
        accumulated += token;
        await emitSSE(pieceId, token);  // SSE para o frontend
      }
    }

    // Salvar peça final
    await step.run('save-piece', () =>
      db.documents.update({
        where: { id: pieceId },
        data: {
          content: accumulated,
          status: 'REVIEWING',
          iaModel: routeModel(type),
          iaTokensInput: stream.usage.input_tokens,
          iaTokensOutput: stream.usage.output_tokens,
          iaCostCents: costCents(stream.usage, routeModel(type)),
          iaGeneratedAt: new Date(),
        }
      })
    );

    // Notificar user
    await step.run('notify', () =>
      notifyUser(userId, {
        type: 'PIECE_READY',
        title: 'Peça pronta',
        body: `Sua ${schema.label} está pronta para revisão`,
        link: `/pieces/${pieceId}`,
      })
    );
  }
);
```

## Mecanismo Anti-Alucinação

### Verificador de Citações

```typescript
async function verifyCitations(text: string): Promise<VerificationResult> {
  // 1. Extrair todas as citações
  const citations = extractCitations(text);
  // Ex: ["art. 5º, XXXV, CF", "Súmula 309 STJ", "Tema 988 STJ"]

  // 2. Para cada citação, verificar
  const verified: VerifiedCitation[] = [];
  const unverified: UnverifiedCitation[] = [];

  for (const cite of citations) {
    const result = await citationVerifier.verify(cite);
    if (result.found && !result.divergente) {
      verified.push({ cite, source: result.source });
    } else {
      unverified.push({
        cite,
        reason: result.reason || 'não encontrada',
        shouldWarnUser: true,
      });
    }
  }

  return { verified, unverified };
}
```

**Importante:** Toda peça gerada exibe um banner: "⚠️ Revise todas as citações antes de protocolar. A IA pode alucinar referências."

Esse aviso é **obrigatório** por compliance OAB + proteção civil do escritório.

## Custos IA — Projeções

### Hipóteses
- 500 tenants pagantes, média 30 peças/tenant/mês
- Total: 15.000 peças/mês

### Mix de modelos
- 60% Sonnet (~9.000 × R$ 0,30) = R$ 2.700
- 20% Opus (~3.000 × R$ 0,90) = R$ 2.700
- 20% Haiku (~3.000 × R$ 0,05) = R$ 150

**Total**: ~R$ 5.550/mês

### RAG + Embeddings
- 5.000 buscas/dia × 1.000 vetores = 5M index updates/mês
- Voyage: $0,12/M tokens
- Estimado: R$ 200/mês

**Total IA mês:** ~R$ 5.750

Comparado ao MRR de 500 × R$ 149 = R$ 74.500, isso é **7.7% de custo** — sustentável.

## Compliance com OAB

- Toda peça gerada traz aviso: "Documento gerado por IA. Revisão humana obrigatória. Juris-Flow não se responsabiliza por conteúdo gerado automaticamente."
- Usuário deve marcar checkbox "Li e revisei" antes de exportar PDF final
- Log disso em `audit_logs`
- IA treinada para:
  - Não prometer resultado ("você vai ganhar")
  - Não fazer juízo moral do juiz
  - Sugerir consulta a advogado se complexidade alta
- Proibido treinamento com dados de clientes (Anthropic ToS já garante isso)
